# 0.5.0 — 2026-10-28

## Added

- **`workflows-guide` skill**, served as `skill://workflows-guide/SKILL.md` (template `skill://{+path}`) through `createApp({ skills })` (mcp-ts-core 0.13.18). It covers version pinning, where `name` and `version` come from, step placeholders, draft promotion, and the user-confirmed delete.
- **Root `plugin.json` and `mcp.json`**, the Agent Plugins 1.0.0 pair (mcp-ts-core 0.13.18).

## Changed

- **`workflow_delete` `not_found` recovery hint** now ends "then retry with the exact name and the version to delete." It previously ended "then retry; omit version to target the latest."
- **Raw `content[]` text** escapes the last `#` of a trailing ` #` run and encodes edge Unicode whitespace as numeric references (mcp-ts-core 0.13.18, [cyanheads/mcp-ts-core#781](https://github.com/cyanheads/mcp-ts-core/issues/781)). Rendered Markdown reads the same.
- **Desktop `.mcpb` bundles** drop the framework's build-only files (mcp-ts-core 0.13.18, [cyanheads/mcp-ts-core#791](https://github.com/cyanheads/mcp-ts-core/issues/791)) and keep the MCP SDK skills runtime through a local packaging-script fix (open upstream: [cyanheads/mcp-ts-core#794](https://github.com/cyanheads/mcp-ts-core/issues/794)).
- **`.mcpbignore` paths** are root-anchored (mcp-ts-core 0.13.18).
- **Install age guard** (`minimumReleaseAge`) is 1 day (mcp-ts-core 0.13.17).
- **Docs** now say global instructions are returned as the `globalInstructions` field of `workflow_get`; they are not prepended.

## Fixed

- **`workflow_list` empty-result notice and `workflow_delete` duplicate-file notice** render the text they embed literally in `content[]`. Markdown in a filter value or a workflow name, path, or version is escaped, and every line of the notice stays inside the block quote. `structuredContent.notice` still carries the text exactly as written. Before, that text rendered as live Markdown, and a line break in a filter value ended the block quote.
- **HTTP transport memory under Bun**, the Docker image's runtime: 0.4.2 retained memory for every request. The framework fix releases it when each response ends (mcp-ts-core 0.13.17, [cyanheads/mcp-ts-core#786](https://github.com/cyanheads/mcp-ts-core/issues/786)).

## Dependencies

- `@cyanheads/mcp-ts-core` ^0.13.16 → ^0.13.18 (brings `@modelcontextprotocol/server` ^2.3.1 → ^2.4.0 in 0.13.17).
