# 0.3.3 — 2026-09-19

## Changed

- **`createApp` declares `sessionMode: 'stateless'`** in `src/index.ts` ([#23](https://github.com/cyanheads/workflows-mcp-server/issues/23)) — the HTTP session posture is stated in code instead of depending solely on `MCP_SESSION_MODE`; the env var still overrides when set to a meaningful value.
- **An argument rejection carries a reason, a recovery hint, and a retryable trailer** (mcp-ts-core 0.13.3, 0.13.5) — the `InvalidParams` (`-32602`) envelope now sets `data.reason: "invalid_arguments"` and a `data.recovery.hint` derived from the schema, which `content[]` mirrors as a `Recovery: <hint>` line before closing with `(reason … · not retryable)`. A required field omitted from an enum or literal renders as missing rather than as a wrong choice, and a union rejection renders its branch messages instead of `Invalid input`.
- **Tool arguments pass an ordered pre-validation step** (mcp-ts-core 0.13.4) — a client-added root key is dropped, an undeclared key whose case-folded form names exactly one declared key is rewritten to it, and a JSON-stringified array that fails to parse is repaired and re-parsed once. A call that still fails gets the identical rejection, and the advertised `inputSchema` is unchanged.
- **Framework skills, scripts, and agent docs synced to the mcp-ts-core 0.13.6 templates** — adds `.github/workflows/codeql.yml` (the one workflow this server carries), a `lint:packaging` check that the README `Version-` badge matches `package.json`, the `lint` block in `devcheck.config.json` that carries the definition linter's truncation allowlist, and the session-posture and shutdown sections in `CLAUDE.md` and `AGENTS.md`.

## Fixed

- **`WorkflowIndexService`'s `fs.watch` handle and debounce timer are released on shutdown** ([#25](https://github.com/cyanheads/workflows-mcp-server/issues/25)) — `createApp({ teardown })` calls the new `shutdownWorkflowIndexService()`, so neither ref'd handle outlives teardown, where `SIGTERM` previously left the process resident until `SIGKILL`. A signal shutdown exits the process once cleanup settles either way from mcp-ts-core 0.13.1 on, so the handles are now released rather than cut.
- **A shutdown landing during the first index build no longer opens a watcher** — `initWorkflowIndexService()` starts `init()` without awaiting it, so teardown could run while the build was still in flight and the watcher would open afterwards with nothing left to abort it.
