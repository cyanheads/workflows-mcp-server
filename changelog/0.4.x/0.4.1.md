# 0.4.1 — 2026-10-07

## Changed

- **`@cyanheads/mcp-ts-core` ^0.13.6 → ^0.13.13** — error results end with `request <id>` and carry `data.requestId` (cyanheads/mcp-ts-core 0.13.10, [#576](https://github.com/cyanheads/mcp-ts-core/issues/576)); argument rejections name the field path (0.13.9, [#493](https://github.com/cyanheads/mcp-ts-core/issues/493)).
- **Error data no longer carries stack traces** (0.13.7, [#519](https://github.com/cyanheads/mcp-ts-core/issues/519)), **request context** (0.13.8, [#548](https://github.com/cyanheads/mcp-ts-core/issues/548)), or **`rootCause`** (0.13.13, [#644](https://github.com/cyanheads/mcp-ts-core/issues/644)).
- **`ctx.inputs` keeps only answers the client's declared capabilities cover** (0.13.10, [#496](https://github.com/cyanheads/mcp-ts-core/issues/496)) — a client that did not declare elicitation can no longer pre-answer `workflow_delete`'s confirmation.
- **`ctx.recoveryFor` forwards dropped from the tool definitions** — callers receive the same declared recovery hints; the framework now fills them (0.13.10, [#579](https://github.com/cyanheads/mcp-ts-core/issues/579)).
- **Docker image installs dependencies in a build-platform `deps` stage** and prunes musl-only native bindings; the image no longer sets `MCP_FORCE_CONSOLE_LOGGING`, and Bun is 1.4.2.
- **`server.json` npm entries use `runtimeHint: "npx"` and drop the `run start:*` arguments**; the streamable-http entry sets `MCP_TRANSPORT_TYPE=http`.
- **`.env.example` is regrouped and documents `MCP_REQUEST_STATE_KEY` (opt-in), `LOG_TOOL_FAILURE_PAYLOADS`, `LOG_LLM_INTERACTIONS`, and the OTLP base, traces, metrics, and logs endpoints.** Its transport, storage, and log-level defaults are commented out, so a copied `.env` takes the server defaults.
- **README** documents `MCP_REQUEST_STATE_KEY` and `LOG_TOOL_FAILURE_PAYLOADS` and condenses the tool sections to each tool's contract.
- **CodeQL workflow runs one job per language**, each uploading under `/language:<language>`.
- **Ignore files** — `.gitignore` and `.dockerignore` match `.env*` (`.gitignore` keeps `.env.example`, `.env.template`, `.env.sample`); `.dockerignore` also excludes the MCP registry token files; `.mcpbignore` excludes `docs/idea.md`, `logs/`, and `.cache/`; `package.json` `files` excludes `dist/*.mcpb`.
- **Framework skills and scripts resynced** — `framework-skills/`; the `devcheck`, `lint-mcp`, `lint-packaging`, `check-skill-versions`, `check-framework-antipatterns`, and `release-github` scripts updated; `scripts/install-otel.ts` and `scripts/prune-musl-packages.ts` added.
- **`CLAUDE.md` / `AGENTS.md` synced to the framework template.**

## Security

- **`workflow_delete`'s pending confirmation record now stores the tenant, auth client ID, and auth subject it was issued to.** A round-two answer from any other caller redeems nothing: it fails `confirmation_invalid`, deletes nothing, and spends the record, so the original caller must ask again. The `confirmation_invalid` contract text now names that case. Stdio and `MCP_AUTH_MODE=none` callers are a single principal, so their behavior is unchanged.
