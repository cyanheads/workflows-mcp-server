# 0.4.0 — 2026-09-23

## Added

- **`workflow_delete` confirms the resolved target with the user before deleting** ([#17](https://github.com/cyanheads/workflows-mcp-server/issues/17)) — the first call returns an elicitation prompt naming the resolved `name@version`, its source, and its file path; the file is removed only on an accepted `confirm: true` that still matches a fresh resolution and content hash.
- **`workflow_create_temp` reports `status: "created" | "overwritten"`** ([#20](https://github.com/cyanheads/workflows-mcp-server/issues/20)) — an overwrite keeps the replaced draft's `created_date`, and the temporary-draft notice now also reaches `structuredContent` via a declared `enrichment` field.
- **`workflow_delete` output adds `source: "permanent" | "temp"`** ([#18](https://github.com/cyanheads/workflows-mcp-server/issues/18)).

## Changed

- **HTTP startup with `MCP_SESSION_MODE=stateless` now fails** ([#17](https://github.com/cyanheads/workflows-mcp-server/issues/17)) — `workflow_delete`'s confirmation round needs a live session, so `createApp` declares `sessionMode: { default: 'stateful', require: 'stateful' }`; the Dockerfile and `.env.example` default to `stateful`. Stdio is unaffected.
- **Temporary workflows are persistent drafts, not session-scoped** ([#18](https://github.com/cyanheads/workflows-mcp-server/issues/18)) — a draft stays under `temp/` until deleted with `workflow_delete`; nothing expires it.
- **Workflow identity is canonicalized end to end** ([#26](https://github.com/cyanheads/workflows-mcp-server/issues/26), [#16](https://github.com/cyanheads/workflows-mcp-server/issues/16), [#33](https://github.com/cyanheads/workflows-mcp-server/issues/33)) — `version` is stored, indexed, and looked up as `semver.valid()`'s canonical form (a leading `v` and build metadata dropped); `workflow_get`/`workflow_delete` reject a non-semver `version` before lookup and trim `name` before it.
- **Filenames carry a content hash** ([#21](https://github.com/cyanheads/workflows-mcp-server/issues/21), [#29](https://github.com/cyanheads/workflows-mcp-server/issues/29)) — `<name-slug>-<version-slug>-<8-hex-hash>-workflow.yaml` keeps keys whose slugs collide (case, punctuation, non-Latin names) at distinct paths; a name with no ASCII letters or digits now stores under the placeholder slug `workflow` instead of failing as `invalid_name`.
- **One index entry per `name@version` across sources** ([#19](https://github.com/cyanheads/workflows-mcp-server/issues/19)) — `workflow_create` and `workflow_create_temp` each reject a key the other source already holds with `already_exists`; a rebuild resolves an on-disk collision to the permanent file.
- **`workflow_list` filtering and sorting are correct** ([#15](https://github.com/cyanheads/workflows-mcp-server/issues/15), [#28](https://github.com/cyanheads/workflows-mcp-server/issues/28)) — `query`/`category`/tag filters are trimmed before matching, and version ordering uses full semver precedence so a prerelease no longer ties with its release.
- **Required text fields reject whitespace-only values** ([#22](https://github.com/cyanheads/workflows-mcp-server/issues/22)) — `name`, `description`, `author`, `category`, and step `server`/`tool` are checked both at the create tools and at the index loader.
- **Writes and deletes are serialized in-process** ([#30](https://github.com/cyanheads/workflows-mcp-server/issues/30)) — closes a race where two concurrent creates of one key in different categories could both succeed.

## Removed

- **`temp_not_allowed` error reason** ([#18](https://github.com/cyanheads/workflows-mcp-server/issues/18)) — temporary drafts are deletable now; see Changed.

## Fixed

- **Deleting the last workflow in a category removes the now-empty category directory** ([#24](https://github.com/cyanheads/workflows-mcp-server/issues/24)) — `workflow_create` recreates the directory and retries once if a concurrent cleanup wins the race.
- **A same-key file left after a delete is now surfaced** ([#32](https://github.com/cyanheads/workflows-mcp-server/issues/32)) — the result carries a notice naming the file `workflow_get` now returns for the key.
- **`write_failed` and `delete_failed` messages never leak the absolute workflows path** ([#31](https://github.com/cyanheads/workflows-mcp-server/issues/31)) — every syscall's error, not just `open`'s, is scrubbed.
